# Mobile data and permission inventory

Inspected 8 September 2026 for [spec #459](mobile-app-spec.md). This describes the current local implementation, including unfinished behavior. It is input to the privacy policy and store declarations, not a published policy or an assertion that the app is ready for distribution. Hosting settings, processor retention and the final signed binaries still need verification.

## Native dependencies and permissions

The lockfile pins Capacitor core/iOS/Android **8.5.1**, App **8.1.1**, Browser **8.0.4**, Clipboard **8.0.1**, Geolocation **8.2.2**, Preferences **8.0.1**, Share **8.0.1**, Keep Awake **8.0.1** and `capacitor-secure-storage-plugin` **0.13.0**. React, Router, Socket.IO, Zustand and Supabase JS also ship in the web bundle. No advertising, contacts import, push, payment or third-party crash-reporting SDK is configured in this implementation. That statement is based on the checked dependency/configuration surface, not a final runtime traffic audit.

| Native function | Current declaration and behavior | Verification still needed |

Called only by an explicit location action with `enableHighAccuracy: false`. No background location/watch is used. | Both permission outcomes and approximate mode on physical devices. | Preferences | Lightweight local state and an installation marker; not encrypted storage for credentials. | Backup/restore behavior and accessible local-clear wording. [Capacitor documents the required UserDefaults reason](https://capacitorjs.com/docs/apis/preferences). |

| Keep Awake | Active Cook View only; releases on background/exit. | Physical power/lifecycle behavior; no reason to add background execution or unrelated permissions. |

The observed SwiftPM graph contains Capacitor **8.5.1**, `ion-ios-geolocation` **2.1.1** and SwiftKeychainWrapper **4.0.1**, plus the local plugin packages. The compiled Android Debug dependency graph resolves `iongeolocation-android` **2.2.2**, Play Services Location **21.3.0**, Gson **2.13.2** and Kotlin coroutines **1.10.2**. Its merged manifest includes INTERNET, COARSE_LOCATION, FINE_LOCATION, ACCESS_NETWORK_STATE and the app's signature-protected dynamic-receiver permission. It disables backup and uses the Debug loopback network-security configuration. Local evidence is in `output/mobile/android-debug-dependencies.log` and `android-artifact-evidence.json`. Record and review the release graph/manifest separately before release approval.

The Android storage finding was confirmed by reading `PasswordStorageHelper.java` and `SecureStoragePluginPlugin.java` from the installed 0.13.0 package. The [patch](../patches/capacitor-secure-storage-plugin+0.13.0.patch) is applied by `mobile:sync`; Android settings reject an unpatched or unexpected helper before compilation. This preserves the existing dependency/adapter and encrypted format. [Device tests](../frontend/android/app/src/androidTest/java/it/com/dinder/app/SecureStorageTest.java) cover an encrypted round-trip, corrupted ciphertext, initialization failure without plaintext fallback and failed disk commits, using isolated test keys/preferences. App/instrumentation APK compilation and all three tests pass after the authorized SDK installation, using the AOSP API 36 ARM64 emulator. The result does not establish physical hardware-backed storage or process-recovery behavior. Local evidence: `output/mobile/android-storage-tests.log` and `android-storage-tests.xml`. A package's claim to use Keychain/Keystore is insufficient evidence of failure behavior.

## Binary evidence and limitations

The inspected artifact is the ad-hoc signed iOS simulator Debug build recorded in ignored `output/mobile/artifact-evidence.json`, binary SHA-256 `08120e284045f0f9a3c278182ce68e16c98e3434337fe4d5181ed02c2a11d503`. It uses local guest-only services and blank Supabase settings, so it cannot prove actual authentication traffic or production processor behavior.

It contains three privacy manifests: the app's `PrivacyInfo.xcprivacy`, `Capacitor.framework/PrivacyInfo.xcprivacy` and `Cordova.framework/PrivacyInfo.xcprivacy`. The framework manifests declare no accessed API/collection categories and no tracking. The app manifest declares no tracking and UserDefaults reason **CA92.1**. The built Info.plist has the foreground location usage text. Android Debug APK and merged-manifest evidence is now recorded, but there is no signed physical distribution archive or release Android binary proof. An SDK manifest is not the app's complete disclosure of data sent to its own backend.

## Disclosure and release work left

1. Compile and verify the patched secure storage before the Android prototype. Exercise failed encryption/read/write, first install, process kill, reinstall and backup restore without silently turning a storage error into fresh admission or credential loss.
2. Complete identity, deletion and safety implementation, then update this inventory to its actual schemas and UI. Keep server deletion separate from other people's shared guest data and local device cleanup.
3. Identify the legal operator, privacy/support contacts, actual processing regions, sub-processors, log/back-up retention and access controls for Railway, Supabase, Google, Apify, recipe/retailer services and image hosts. Cloudflare DNS/R2 and any edge proxy features must be described according to enabled production settings. OpenAI/Gemini/TMDB corpus generation is operator work, not a runtime participant-data upload; verify this remains true in release.
4. Map account identifiers/email/avatar and social graph, search/location, dietary input, other shared content, product interactions and diagnostics to the actual store questionnaire. Dietary information can reveal health needs or beliefs: do not classify it as innocuous catalogue data by default. Do not select “no data collected” because guests need no account or because some data expires.
5. Determine linked-to-user status and service-provider sharing from actual identifiers, log correlation and contracts. Apple requires app and relevant partner practices to be considered; Google includes SDK behavior and distinguishes off-device collection, sharing and ephemeral processing. These determinations remain open, not automatic conclusions from a library name. [Apple privacy details](https://developer.apple.com/app-store/app-privacy-details/), [Google Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469).
6. Inspect final signed artifacts, SDK privacy manifests/signatures and Android merged permissions; capture traffic on the ordinary guest, Google/Apple, list, report and deletion journeys. Reconcile that evidence with policy text, store answers and actual retention jobs before beta/review approval.

Current logging corrections are local only. Contract checks preserve useful request correlation/status while omitting automatic credentials/private URL content; the real Redis Claim race also verifies no Shopper names or list capability reach the captured logs. The existing Caddy serving check verifies private-link requests remain functional and absent from its log output. [Caddy's field filtering](https://caddyserver.com/docs/caddyfile/directives/log) supplies the access-log filter. None of these checks certifies external hosting logs or erases logs from earlier deployments.
