# Woolworths' public search API is the grocery pricing source

The cook branch prices shopping lists by calling Woolworths' public search endpoint (`POST /apis/ui/Search/products` on woolworths.com.au) directly from the backend — the same JSON API the retailer's own web storefront uses. No vendor sits in the middle, no HTML is scraped, and no challenge is circumvented: Akamai Bot Manager sees our real IP and traffic shape and admits them ([#242](https://github.com/Zacplischka/dinner_app/issues/242) measured 194 requests from production's egress, all 200, with no degradation at any rate tried). This is a distinct and lower risk class than ADR 0004's — no vendor, no scraping, no circumvention — which is why it gets its own record rather than an amendment. Woolworths was chosen over Coles on access grounds alone ([#240](https://github.com/Zacplischka/dinner_app/issues/240): Coles blocks headless clients behind Imperva after ~4 requests, stickily; Woolworths answers plain HTTP the same minute).

The route bundles the following commitments (settled in [#233](https://github.com/Zacplischka/dinner_app/issues/233)):

- **Identity.** Akamai 403s any User-Agent that is not a verbatim browser string — an honest `Dinder/1.0` UA was tested and rejected at the seed request, alone and as a suffix. We therefore send one pinned browser UA we are not, and carry our real identity where Akamai permits it: `From: zacplischka@gmail.com` and `X-Requested-With: Dinder/1.0 (+https://github.com/Zacplischka/dinner_app)` on every request, verified to pass. The UA is a constant — never rotated or randomized, since rotation is the fingerprint evasion this decision renounces.
- **Self-rate-limiting is a v1 requirement, not an optimisation.** #242 found no ceiling to stay under, so the budget is chosen restraint rather than measured margin: the shared cache is served first and always, and every cold lookup passes through one global queue (app-wide concurrency 1) with a 500 ms floor between request starts. The whole app never asks more of Woolworths than one engaged human browsing the site, regardless of user count — the cache absorbs scale, not the queue. A fully cold 12-line list prices in ~7–9 s and fills progressively.
- **Stable Australian egress.** Woolworths picks the fulfilment store from the caller's apparent location; Railway's US-West egress is served store 1101 where residential AU gets 3221, moving catalogue, ranking, availability, and fresh-produce prices 10–30% (#242). Woolworths calls route through one static Australian IP — a dumb forward proxy, no rotation — so production is served an Australian store and the matching measurements ([#231](https://github.com/Zacplischka/dinner_app/issues/231)) describe what production actually returns. One egress still means one store nationally: the tally is approximate for users far from that store, an approximation the ≈-tally ([#234](https://github.com/Zacplischka/dinner_app/issues/234)) already carries.
- **Cache.** Search term → top-5 trimmed candidates (~1–2 KB) in Redis, keyed `(FulfilmentStoreId, term)` with the store id read off each response. Cardinality is 1 today, but a store flip under us becomes a cache miss that self-heals instead of silently serving another store's prices. Freshness Window semantics (ADR 0005's concept) are reused: a successful entry lives `min(24 h, time to Wednesday 6 am AEST)` — the weekly specials rollover is the one systematic repricing event — and a failure retries after ~1 h. No price-age UI; with a ≤24 h window, "Prices from Woolworths" is truthful as-is.
- **The promised price is `Price` (online).** The deep link lands on the online product page, and the tally must never disagree with the page we send the user to. `InstorePrice` rides along in the cached record and divergence is counted; the two have never differed in any measurement (0/80 at both egress points, and again live).

## Consequences

- The endpoint is unofficial and revocable at will. If Woolworths blocks or objects, we comply rather than escalate — no proxy pools, no fingerprint-evasion stack, no arms race (#240's commitment, made durable here). Lists degrade to #234's Unpriced/Unmatched line states; the cook branch survives losing the source.
- Marginal cost per priced list is ~zero: a cold 12-line list is ~1.3 MB of free API traffic through the proxy, a warm one is a Redis read. The real cost is the fixed AU egress box (~$5–10/mo), which keeps total fixed cost under the $120/mo monetization trigger ([#228](https://github.com/Zacplischka/dinner_app/issues/228)).
- Aisle numbers stay out of v1 on evidence: the payload carries online shop-department taxonomy (`piescategorynamesjson`), no aisle field of any kind — weaker than Coles' named `onlineHeirs[].aisle`, which itself didn't survive the ruling. The category strings stay in the cached record as re-ranker signal only.
- The UI names Woolworths (#240): receipt-matching is a claim about one retailer, and this ADR is where that claim's accepted approximations live — one store nationally, prices up to 24 h old, online price promised.
